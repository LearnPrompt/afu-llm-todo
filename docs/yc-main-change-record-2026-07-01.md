## 一句话总结

这轮改动没有把项目彻底改成另一个产品，仍然保留“收件箱 → 转卡 → 排期池 → 周历 → Markdown / 外部日历”的主流程。主要工作是把它从一个偏演示性质的内容选题规划器，推进成一个更适合真实本地 Vault 和 macOS Calendar 测试的版本，并补上转卡、撤回、排期失败降级、暗色模式等关键交互。

## 基线情况

上游远端的 `v1.3.4` 已具备收件箱扫描、转选题卡、排期池、周历、Markdown 回写、飞书和 macOS 日历同步等能力，但实际测试中暴露了几类问题：

- 新目录尚未建立时，部分读取接口会直接报错。
- macOS 日历名留空时可能选中只读日历，排期接口返回 500。
- 外部日历同步失败会打断整个排期，导致本地 Markdown 也不能稳定落盘。
- 转卡后直接进入排期弹窗，用户没有“先放进排期池”的选择。
- 转卡、排期、撤回等连续操作缺少明确状态和防重复提交保护。
- 暗色模式只覆盖了部分组件，后续新增的分页栏等区域仍可能使用写死的浅色背景。
- 浏览器控制台里的 `contentscript.js`、`ObjectMultiplex`、`MaxListenersExceededWarning` 来自浏览器插件注入，不是 Afu 页面自身的核心报错。真正影响流程的是 `/api/topics/schedule` 的 500。

## 前次检查点

以下内容已经包含在个人仓库的 `main` 提交 `b5d5406` 中。相对远端基线共涉及 72 个文件，约新增 2871 行、删除 118 行。

### 工作区默认值

- 默认行动卡目录从 `15_自媒体/选题库` 改为 `40_行动卡片`。
- 默认归档目录改为 `99_系统/归档/行动卡片`。
- 默认 Wiki 目录改为 `30_整理Wiki`，对应 index 和 log 路径同步调整。
- 配置测试随默认目录一起更新，保持默认值和测试断言一致。
- 当收件箱、Wiki Todo 等目录暂时不存在时，扫描逻辑返回空列表，不再因为 `ENOENT` 直接中断首次配置流程。

### 排期可靠性

- 排期、撤回排期、作废和撤回转卡等写操作增加了按卡片路径执行的 mutation lock，降低同一张卡被并发修改的风险。
- 保存排期时增加 `scheduleSubmitting` 状态，按钮会显示“保存中…”，避免连续点击造成重复写入。
- 前端只有在排期 API 真正成功后才关闭弹窗并继续下一张排期队列。
- 排期结果会把 `calendarProvider`、`calendarSyncStatus`、macOS 日历名和事件 ID 回写到 Markdown 和操作日志。

### 同步失败降级

原先外部日历创建失败会让 `/api/topics/schedule` 整体返回 500。现在调整为：

- 先形成完整的本地排期状态。
- 外部日历同步成功时记录事件 ID 和实际日历名。
- 同步失败时仍保存 Markdown，只把 `calendar_sync_status` 标成“同步失败：具体原因”。
- 前端明确提示“排期已保存，但外部日历同步失败”，不会让用户误以为本地排期也丢失。
- 切换为“只写 Markdown”时，会尽力清理以前的外部日历事件；清理失败不会阻断本地保存。

这项调整的核心原则是：本地 Markdown 是主数据，外部日历是可降级的同步目标。

### macOS Calendar

- 新增 `GET /api/macos/calendars`，通过 AppleScript 读取 Calendar.app 的日历列表及可写状态。
- 设置页的 macOS 日历名由手工输入改为下拉选择，只展示可写日历。
- 下拉支持加载中、读取失败、无可写日历和保留旧配置等状态。
- 如果没有指定日历，服务端只选择第一个可写日历，不再盲目选择第一个日历。
- 如果指定日历不存在或为只读，返回明确错误，不再静默写入其它日历。
- 创建事件后记录实际使用的日历名称和事件 UID。
- 删除或重新排期时，可以根据 UID 或卡片 `topic_id` 清理旧事件，减少重复日程。
- macOS 日期由 AppleScript 按本机日期和时间构造，避开此前使用固定时区转换造成的本地时间偏移风险。

实际测试时已经成功读取可写日历，并完成写入 `Default` 日历的排期验证。后续正式使用时仍建议选择一个明确的个人日历，例如 `Home` 或 `Work`，不要依赖默认顺序。

### 转卡流程

原流程是转卡成功后直接把用户送进排期弹窗。现在改成两段式：

1. 转卡成功后先显示“转卡完成”结果弹层。
2. 用户选择“先放排期池”或“现在排期 / 逐条排期”。

这样做的原因是“转卡成功”和“决定什么时候排期”是两个不同动作。用户可以继续整理收件箱，也可以立即安排日历，不再被流程强行推进。

同时补充了：

- 单条和批量转卡结果列表。
- 批量失败数量提示。
- 合并到已有卡片时的明确说明。
- 转卡成功不再同时弹 Toast 和排期 Dialog，减少重复反馈。
- 新增“撤回转卡”，可以删除刚生成的行动卡，让原始收件箱素材重新出现在候选池。

### 排期与作废

- 排期弹窗加宽，时间、同步目标和当天已有排期更容易阅读。
- 每日收件箱、排期、作废、飞书授权和转卡结果弹窗统一使用圆形 `×` 关闭按钮。
- “撤回排期”会询问是否同时删除外部日历事件。
- 作废界面补充动作解释：
  - “拒绝”保留行动卡，只从排期池和周历隐藏，不删除收件箱原素材。
  - “归档”把行动卡移出活动目录；如果有关联来源，则说明原始素材也会被处理。
- 提示文案区分本地 Markdown、飞书和 macOS 三种同步结果。

### 暗色模式

提交 `b5d5406` 已经补充以下暗色 surface：

- inline confirm
- 每日收件箱条目和确认区域
- macOS / 飞书授权信息区域
- 转卡结果列表
- 当天已有排期列表
- 日历列、容量标签、快捷时段、原因标签和空状态
- 统一后的圆形关闭按钮

这批改动解决了新增弹层和列表在暗色模式下出现突兀白块的问题，但当时仍遗漏了后续新增的排期池分页容器；该遗漏已在当前本地工作区继续修复，见下文。

### 分页暗色修复

排期池的 `.backlog-controls` 原本把浅色渐变写死在组件样式里。暗色模式下容器仍然发白，而文字继承暗色主题的浅色值，因此出现低对比、像“内容消失”的问题。

当前本地修复为：

- 新增语义化 `--control-surface` 主题变量。
- 亮色模式保留原有浅色渐变。
- 暗色模式使用低亮度暖灰渐变。
- 分页容器边框统一使用 `--line` 主题变量。

浏览器已经实际检查暗色和亮色两种状态：分页文字、按钮和选择框均可读，页面控制台没有 Afu 自身错误。

### 飞书连接状态

- 本机已安装 `lark-cli 1.0.62`。
- 用户身份 `YC` 的 token 有效，但目前只有基础身份、联系人和消息撤回权限。
- 首次 Calendar 授权意外生成了包含大量无关业务权限的 `1.0.1` 版本申请，该申请已经撤回。
- Afu 后续只应申请 `calendar:calendar:read`、`calendar:calendar.event:create` 和 `calendar:calendar.event:delete`。
- 这三个最小 Calendar 权限尚未完成重新申请与管理员审批，因此飞书真实日历同步仍不能标记为通过。
- CLI 配置、App Secret、用户 token 和设备授权码均存放在仓库之外，本次提交不包含这些凭据。

## 后续同步

日常在个人仓库继续开发：

```bash
git add -A
git commit -m "..."
git push
```

需要查看上游远端的新改动时：

```bash
git fetch upstream
git log --oneline main..upstream/main
```

确认要吸收上游远端更新后，再根据差异选择 merge 或 rebase。由于当前直接在个人 `main` 开发，操作前应先确保工作区干净并留好 checkpoint。

未来需要合并回上游远端时，由用户手动从 `ycl-2004/afu-llm-todo:main` 向 `LearnPrompt/afu-llm-todo:main` 创建 PR。开 PR 前建议先做三件事：

1. 把产品代码、通用文档和个人测试数据分开审查。
2. 移除不适合上游的本机绝对路径、个人日历名和真实测试日志。
3. 拉取最新 `upstream/main`，解决冲突后重新运行完整测试和 UI 验收。

## 当前结论

当前个人版本已经比上游远端的 `v1.3.4` 更适合做本地 Vault 与 macOS Calendar 的连续测试。最大的改善不是增加更多按钮，而是把失败边界理清：本地 Markdown 优先保存，外部日历允许失败；转卡和排期拆成两个决定；危险或可撤回操作给出明确说明。

接下来最重要的是继续用真实流程找问题，但在提交和未来 PR 时，把“通用产品改动”和“YC 个人测试数据”分开处理。
