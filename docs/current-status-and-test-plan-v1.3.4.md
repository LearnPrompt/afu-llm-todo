- 它本质上还是“内容选题规划器”，不是通用个人行动系统。

# 一、这个网站到底是做什么的

项目入口和定位见 [README.md](../README.md) 和 [SKILL.md](../SKILL.md)。

它由三部分组成：

1. Node.js 本地服务

   使用原生 HTTP 模块，没有数据库，也没有第三方 Web 框架。核心在 [server.mjs](../server.mjs#L73)。

2. 原生 HTML/CSS/JavaScript 网页

   页面结构在 [index.html](../public/index.html)，交互在 [app.js](../public/app.js#L140)。

3. Agent Skill

   Agent 可以扫描收件箱、生成 Wiki packet、生成 Todo 候选，再调用本地 API 写回 Markdown。

所有正式数据都存在 Markdown 文件及其 frontmatter 中，没有额外数据库。

## 当前网页能完成的流程

### 1. 配置工作区

支持两种模式：

- Obsidian 模式：填写 Vault 根目录和相对目录。
- 独立模式：填写三个绝对目录。

可配置：

- 收件箱目录
- 选题/行动卡目录
- 归档目录
- 每日推荐容量
- 快捷时间段
- Markdown、飞书或 macOS 日历同步

但独立模式目前实际不可完整使用，后面会具体说明。

### 2. 扫描收件箱

系统递归扫描收件箱里的 `.md` 文件，并排除：

- `README.md`
- 点号开头文件
- `attachments/`
- `images/`
- frontmatter 中 `status: processed` 的文件
- 已经被选题卡通过 `source_inbox_path` 或 `source_url` 引用的文件

候选卡会提取：

- 标题
- 作者
- 来源
- 保存时间
- 标签
- 前三段摘要
- 置信度
- 缺少链接、正文太短、标题模糊等警告

置信度只是规则判断，不是 LLM 判断。

### 3. 直接转卡

点击“让阿福转卡”后，它会创建一张 Markdown 卡片。

默认模板仍然是内容创作模板：

- `type: 选题策划`
- `target_forms: 视频`
- `选题判断`
- `可拍主张`
- `开头钩子`
- `主体结构`
- `结果展示`

所以即使目录叫“行动卡片”，本质仍是选题卡。

例如当前演示 Vault 中的 `YC_Info` 私人长期资料，也被生成了“视频”形式的选题卡。这和你演示资料里写的隐私边界是冲突的。

### 4. 自动去重合并

转卡时会把中文标题拆成单字关键词。如果新标题与已有标题的关键词重叠达到 50%，就把新素材追加到已有卡片，而不是创建新卡。

问题是：

- 算法比较粗糙，容易误合并。
- 合并后没有记录新素材已经被处理。
- 新素材仍然留在候选池，可以被反复合并。

隔离演练已经实际复现了这个问题。

### 5. 排期池和周历

转卡后，新版本会：

- 自动切到“排期池”
- 自动弹出排期窗口
- 批量转卡时逐张进入排期队列

支持：

- 点击排期
- 拖到某一天
- 选择快捷时间段
- 自定义时间
- 查看当天其他排期
- 时间冲突提示
- 每日推荐容量提示
- 上一周/下一周
- 搜索、阶段筛选
- 过期任务红色标记
- 重新排期
- 取消排期

每日容量只是提醒，不会阻止超量。时间冲突也只是提醒，服务端允许重叠排期。

### 6. Markdown 和外部日历

选择 `none`：

- 只更新 Markdown frontmatter。

选择 `lark`：

- 读取本机 `lark-cli` 登录状态。
- 创建、更新或删除飞书主日历事件。
- v1.3.4 已兼容 `lark-cli 1.x` 的嵌套授权结构。

选择 `macos`：

- 通过 `osascript` 操作 macOS Calendar。

目前外部日历有两个重要限制：

- 服务端固定使用 `Asia/Shanghai` 和 `+08:00`。
- 当前用户环境是 Vancouver，实际同步时间可能偏移 15–16 小时。
- macOS 日历名称找不到时，会静默退回第一个日历，可能写错地方。
- 飞书固定使用主日历，没有专用演示日历配置。

当前配置是 `calendarProvider: none`，所以暂时不会触发这些风险。

### 7. 拒绝和归档

拒绝：

- 卡片文件保留。
- 阶段变为 `已拒绝`。
- 从排期池和周历隐藏。
- 记录原因。

归档：

- 卡片移动到归档目录年份子目录。
- 设计上应该删除对应收件箱源文件。

但实际测试发现，源文件并没有删除，而且会重新出现在候选池。

### 8. 每日收件箱

每日弹窗不是定时任务。

它只有在 URL 包含参数时才打开，例如：

```text
http://localhost:4317/?dailyInbox=1&inboxDate=2026-06-26
```

真正的“每天提醒”仍然需要外部 Agent、定时器或自动化工具负责打开页面或运行 Skill。

### 9. Wiki Mode

后端确实存在 Wiki API：

- 编译 packet
- 生成 Todo 候选
- 接受 Todo
- 拒绝 Todo

但网页已经没有 Wiki 操作入口。

而且“编译 Wiki”并不是真的更新主题页、概念页或知识图谱。它只是生成一个 Markdown packet，里面写着“请 Agent 编译这些素材”。

“生成 Todo”也是规则映射：

```text
1 条收件箱素材 → 1 条 Todo 候选
```

不会真正理解一篇规划并拆成 3–5 个任务。

比如演示资料“本周四件优先事项”，当前网页只会生成一张叫“本周规划怎么转行动卡”的元卡片，而不是生成四张具体行动卡。

所以实际架构是：

```text
网页直接路径：
Inbox → 一份素材对应一张内容选题卡 → Calendar

Agent 路径：
Inbox → 生成 Wiki packet → 外部 Agent 负责真正整理 → Todo Card
```

# 二、v1.3.0 到 v1.3.4 最新改动

远端新增了 8 个提交，代码从 `v1.3.0` 更新到 `v1.3.4`。

## v1.3.1：页面结构重构

主要变化：

- 工作区配置从右侧移动到独立整块。
- 配置默认展开。
- Hero 状态卡由 5 个变成 4 个。
- “题库”统一改名为“排期池”。
- 删除诊断 Tab。
- 删除网页中残留的 Wiki/诊断面板。
- 设置保存后只显示简化诊断 Banner。
- 独立模式文案改成填写三个绝对路径。

影响：

- 对新用户配置更清晰。
- 现有记录中的“题库”应改成“排期池”。
- Wiki 流程不能再通过网页测试，必须拆成 API/Agent 测试。
- 详细诊断能力被隐藏，只能调用 `/api/diagnostics` 或 `npm run verify`。

## v1.3.2：六项交互修复

主要变化：

- 批量转卡发生合并时，返回已有卡片路径，排期窗口不再丢失。
- 转卡后自动切到排期池。
- 自动弹出排期框。
- 批量转卡逐张排期。
- 收件箱工具栏布局修复。
- 作废原因增加六个快捷选项。
- 被拒绝、归档、发布的卡不再显示在周历。
- 过去时间的卡显示“已过期”。
- 飞书授权只保留一个明确入口。
- 显示 `lark-cli` 版本。

注意：合并后的素材会把“已有卡片”放入排期队列，因此用户可能被要求重新排期旧卡片。

## v1.3.3：修复飞书 1.x 授权识别

`lark-cli 1.x` 把用户状态移动到：

```text
identities.user.*
```

旧代码只读顶层字段，导致已经授权也一直显示未授权。新版本已兼容新旧结构。

当前机器没有可用的 `lark-cli`，所以只能确认代码路径，无法确认真实飞书创建、更新和删除事件。

## v1.3.4：明确飞书授权来源

页面现在明确说明：

- 授权来自本机 `lark-cli` 已登录账号。
- 应核对账号是否本人。
- App 自身不保存飞书凭据。

## 对数据兼容性的影响

好消息是：

- Markdown frontmatter 基本兼容。
- 当前演示 Vault 可以正常加载。
- 不需要执行数据迁移。
- `dailyCapacity: 3` 和自定义快捷时段均正常保留。

但最新提交没有增加任何自动化回归或文档更新，这批 UI、飞书和批量转卡修改目前没有回归保护。

# 四、实际发现的问题

| 优先级 | 问题 | 实际影响 |
|---|---|---|
| 阻断 | 当前仍是内容选题系统 | 个人行动会被生成“视频、可拍主张、开头钩子”等错误模板 |
| 阻断 | 没有隐私分类和保护 | `YC_Info` 私密资料可能被当成公开内容选题 |
| 阻断 | 独立模式转卡失败 | 卡片先写入，然后日志尝试写 `/99_系统` 失败，API 返回失败但数据已部分落盘 |
| 阻断 | 外部日历固定上海时区 | Vancouver 用户同步到飞书/macOS 时可能产生严重时间偏移 |
| 高 | 归档没有删除/处理源文件 | 源文件重新出现在候选池，归档流程不能闭环 |
| 高 | 合并素材没有标记已处理 | 同一素材可以反复合并到已有卡片 |
| 高 | 目录路径边界校验错误 | `40_行动卡片-evil` 这类同名前缀目录也会被当成合法选题目录 |
| 高 | 服务监听所有网络接口且无认证 | 局域网可达时可能暴露真实 Vault 操作能力 |
| 高 | 前端吞掉 API 错误 | `postAndReload()` 捕获错误后不向调用者抛出，排期框仍可能关闭并继续下一张 |
| 中 | 卡片摘要显示“选题判断” | 标题被去掉后，Markdown 小标题被误当成摘要 |
| 中 | 卡片日期和日志日期不一致 | 卡片按 UTC/浏览器时间，日志按上海时间，已出现相差一天 |
| 中 | Wiki 名称和实际能力不一致 | API 只生成给 Agent 的 packet，不会自动维护 Wiki |
| 中 | 快捷时间段不会立即刷新冲突提示 | 点击快捷时段后侧栏可能仍显示旧冲突状态 |
| 中 | “去重中”阶段筛选已经失效 | 服务端读取时会把该阶段归一化成“待排期” |
| 中 | 首次配置容错差 | `/api/topics` 先读不存在目录，可能在配置加载前就失败 |
| 低 | 无 CI、无服务端/前端集成回归 | 最新四个版本的主要改动没有自动回归 |
| 低 | 本地 `package-lock.json` 未跟踪且还是 1.3.0 | 不影响当前运行，但会造成版本和工作区卫生问题 |

独立模式问题位于 [topic-planner-config.mjs](../topic-planner-config.mjs#L133) 与 [operation-log.mjs](../operation-log.mjs#L23)。

归档来源字段错误位于 [server.mjs](../server.mjs#L882)。

路径边界错误位于 [server.mjs](../server.mjs#L1752)。

# 五、对我们当前计划的影响

现有安全演示 Vault 方案仍然正确，见 [演示说明](../examples/general-vault/读我-这个GeneralVault怎么玩.md)。

但计划需要增加一个产品决策：

## 方向 A：继续做内容选题规划器

如果目标还是公众号、视频、图文选题：

- 当前模板基本匹配。
- 重点修复去重、归档、时区、独立模式和安全问题。
- 修完后可以较快进入真实 Vault 小范围试用。

## 方向 B：做 All About Me 个人行动系统

如果目标是课程、求职、项目、生活规划、私人长期上下文：

必须先增加：

- 通用行动卡模板，而不是 `选题策划`。
- 一份素材拆成多条具体行动。
- `private/internal/public` 信息分类。
- 私密来源默认禁止生成公开内容。
- `private-context` 标签自动继承。
- 内容任务和私人任务使用不同模板。
- 明确输出物、预计时间、完成标准、证据链接。
- 真正的 Agent/LLM 判断，而不是标题和关键词规则。
- 归档源文件策略：建议标记 processed 或移动到来源归档，不建议默认硬删除。

根据当前演示 Vault 内容，实际目标更接近方向 B。因此这不是简单补几个 Bug，而是需要把“内容选题模型”升级成“领域可配置的行动卡模型”。

# 六、建议演练顺序

## 阶段 1：先修阻断问题

完成后才继续真实试运行：

1. 独立模式日志目录。
2. 统一时区配置。
3. 服务只监听 `127.0.0.1`。
4. 修复严格路径边界。
5. 修复归档来源处理。
6. 合并后将素材标记为 processed 或记录完整来源数组。
7. 前端 API 失败时不要关闭窗口或推进队列。
8. 决定内容卡与通用行动卡模板。

## 阶段 2：自动化回归

至少补以下测试：

- 服务端 API 集成回归。
- 单条转卡幂等性。
- 批量转卡部分失败。
- 合并后候选不再出现。
- 归档后来源处理符合产品决策。
- 拒绝后卡片保留但活动视图隐藏。
- 路径逃逸和同名前缀目录。
- 独立模式完整转卡、排期、归档。
- 上海、Vancouver、夏令时边界。
- 一条规划拆成多个行动。
- 私密资料不生成公开选题。
- Lark 旧版和 1.x 授权状态 fixture。
- Markdown 写入失败时不产生半完成状态。

## 阶段 3：网页手工验收

建议使用安全副本，测试：

- 1440px、1024px、390px 三种宽度。
- 浅色/深色。
- 鼠标与纯键盘。
- 搜索和分页。
- 单条转卡确认。
- 批量转卡队列。
- 合并结果提示。
- 拖拽排期和按钮排期。
- 时间冲突。
- 每日容量超限。
- 跨周导航。
- 过去时间的“已过期”。
- 拒绝预设原因。
- 拒绝后周历消失。
- 归档确认。
- API 失败时界面状态。
- `?dailyInbox=1&inboxDate=2026-06-26`。

## 阶段 4：外部日历

时区修好以后再测。

飞书建议使用独立演示账号，因为当前代码固定写主日历。

测试：

- 未安装 CLI
- 未初始化
- 未授权
- 已授权
- Token 需要刷新
- 网络断开
- 创建事件
- 修改事件
- 删除事件
- 取消排期但保留事件
- 从飞书切换到 Markdown
- 从飞书切换到 macOS

macOS 必须先创建专用演示日历，并取消“名称找不到就写第一个日历”的回退行为。

## 阶段 5：真实 Vault 小范围试运行

只开放：

- 一个演示收件箱子目录
- 一个测试行动卡目录
- `calendarProvider: none`
- 不允许归档删除来源
- 不读取 `YC_Info` 私密区
- 每次只处理 3–5 条

稳定一周以后再扩大范围。
